# Real logo asset wired into BrandMark, wordmark column gap scoped away (review v1)

The header (and every other BrandMark surface) now renders the real `/brand/new-galaxy-furniture-logo.jpeg` instead of the typographic wordmark. The change is three edits plus one asset: `data/site/settings.json` points `logo.src` at the file and declares its intrinsic `736x918`, dropping `site.logo.src` from the placeholder checklist; `BrandMark.astro` scopes the `.ngf-brand` column `gap` to wordmark mode only, so the asset (a single child) no longer inherits dead vertical space that padded the header; and the one contract test that asserted the logo was unsupplied is reconciled to assert the real path, positive-int dimensions, and that the key left the checklist. The asset itself is the user's file trimmed from a 1254x1254 square to 736x918 — background only, artwork preserved.

Watch for: the settings swap also replaces the wordmark in the footer and inside the hero eyebrow, not just the header (confirmed) — a system-wide visual change, not a header-only one. The `.ngf-brand` mobile `min-height:44px` still applies to the asset in asset mode (confirmed), which is intended as a touch target but is the one remaining vertical pad on a 32px image below 768px. Visual/responsive correctness is inferred from built CSS/DOM only; no live browser (confirmed constraint).

**Verdict**: APPROVED

## High-level view

The logo is wired the way the component was designed to accept it: a path plus intrinsic dimensions in settings, and BrandMark switches from the wordmark span to an `<img>` automatically. The built `index.html` carries the `<img>` with `src`, `alt="New Galaxy Furniture"`, `width="736" height="918"`, `loading="lazy" decoding="async"`, wrapped in `<a href="/" aria-label="New Galaxy Furniture home">` — so it renders, keeps aspect ratio (height fixed by CSS, `width:auto`), links home, and is labelled.

The spacing fix targets the actual source of the excess. The old `.ngf-brand` set `flex-direction:column; gap:0.375rem` for the wordmark-over-hairline lockup; in asset mode there is one child, so that gap was dead space under a 32px image. Scoping the gap to `[data-brand-source='wordmark']` removes it for the asset while leaving the wordmark lockup untouched. The champagne hairline was already wordmark-only, so nothing else needed changing.

The placeholder edit matches the store's derivation: `recomputePlaceholders()` drops `site.logo.src` the moment `logo.src` is non-null, so hand-removing it from the committed file keeps the checklist consistent with what an admin save would produce. The reconciled test now fails if the logo is reverted to null, which the old assertion could not detect after the swap.

The asset trim is within the "trim empty background only" constraint: 736x918 is a portrait crop of a square, dimensions match the file on disk and the schema's positive-int requirement, and the intrinsic attributes reserve the box before load so the header does not shift.

### Spacing fix removes the right gap

The excess was `.ngf-brand`'s `flex-direction:column; gap:0.375rem`, which existed for the wordmark-over-hairline rhythm. In asset mode the flex column has a single child, so the gap contributed nothing but a pad under a 32px image. The fix moves the gap onto `.ngf-brand[data-brand-source='wordmark']`, and the built CSS confirms the split:

```css
.ngf-brand[...]{color:inherit;flex-direction:column;text-decoration:none;display:inline-flex}
.ngf-brand[...][data-brand-source=wordmark]{gap:.375rem}
```

The wordmark lockup is byte-for-byte unchanged and only the asset stops inheriting the gap. The other wordmark-only rule (the champagne `::after` hairline) was already gated on `[data-brand-source='wordmark']`, so it needed no edit.

The residual is the ≤767px `.ngf-brand { min-height:44px; justify-content:center }`, still unscoped, so it applies to the asset. It is a deliberate touch-target floor for a homepage link, and centering keeps the 32px mark optically placed — but on mobile it is the one rule that reserves more height than the image needs. If any "excess space below the header" persists on a phone, this is the place to look; on desktop it does not apply.

### The reconciled test is meaningful

The old assertion (`placeholders` contains `site.logo.src`, `logo.src` is null) would pass only while the logo was unsupplied and says nothing once it is set. The new version asserts the real path, `Number.isInteger` positive `width`/`height`, and that `site.logo.src` is no longer in `placeholders` — all of which fail if `logo.src` is reverted to null (the schema would also null the dimensions and the store would re-add the placeholder). It still asserts `site.heroImage` remains, so the "hero is still a swap" half of the original intent is preserved.

### Asset trim stays within the constraint

The file on disk reads 736x918 (verified by parsing the JPEG SOF marker), matching the `width`/`height` in settings and satisfying the schema's `positive().int()` refinement, which the `superRefine` requires whenever `logo.src` is non-null. A portrait crop of a 1254x1254 square is consistent with removing empty margin rather than rescaling artwork; there is no way to confirm from bytes alone that no artwork was clipped, but the preserved non-square ratio and the intact intrinsic attributes are consistent with a background-only trim.

### Reserved box for the image audit

`audit-image-loading.ts` requires the logo `<img>` to sit in a reserved box. Its ancestor `<a>` carries class `ngf-brand-md`, and the built rule `.ngf-brand-md .ngf-brand-asset{height:32px}` registers `ngf-brand-md` as a box-reserving class, so `inReservedBox()` is satisfied — the non-obvious link being that the fixed height lives on a descendant selector keyed off the ancestor's class, not on the `<img>` itself. The briefing reports the audit passing across 25 pages / 67 images.

### Blast radius beyond the header

BrandMark is rendered in three places: the header (`size="md"`), the footer (`size="md"`), and the hero eyebrow (`size="sm"`, `href={null}` → `<span>`). Because the swap is a settings change, the image replaces the wordmark in all three. The built homepage shows the hero eyebrow now rendering the logo image inline before the "Manufacturer & showroom" kicker:

```html
<p class="ngf-hero-eyebrow"><span ... class="ngf-brand ngf-brand-sm ngf-brand-dark">
  <img src="/brand/new-galaxy-furniture-logo.jpeg" alt="New Galaxy Furniture" ...>
</span><span class="ngf-hero-kicker">Manufacturer &amp; showroom</span></p>
```

No component file other than BrandMark changed, so this is not an unrelated edit — it is the designed consequence of enabling the asset. But it is a broader visual change than "header logo + spacing," and the hero eyebrow now leads with a small logo image where it previously led with letterspaced small caps. Worth a confirming glance that this reads as intended rather than as a stray thumbnail.
