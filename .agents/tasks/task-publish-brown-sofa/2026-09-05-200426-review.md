# Publish the Premium 3+1+1 Sofa Set by persisting its published state into the committed JSON (v1)

The live storefront showed zero products because `data/products/brown-sofa.json` was committed as `status: DRAFT` / `published: false` / `images: []`, so `filterCatalogue()` (which keeps only `PUBLISHED`/`OUT_OF_STOCK`) dropped it from every prerendered surface. The admin "Published" state and the four uploaded images lived only in local git-ignored KV/R2 and never reached the repo that Netlify/Cloudflare build from. This change persists the published state into the committed JSON: it adds four real recovered image records, sets `status: PUBLISHED` + `published: true`, designates `primaryImage`, and bumps `updatedAt`, leaving every identity/content field byte-unchanged. The regression test that pinned the old draft state is rewritten to guard the new published state while keeping corner-sofa as an image-less draft, and two new operator-run scripts stage and upload the R2 originals to production.

Watch for: the live image URLs will 404 until the operator runs the production R2 upload — the JSON commit publishes the product but ships no binaries (confirmed). The gallery alt text intentionally dropped the "by New Galaxy Furniture" suffix to pass the keyword-density audit (confirmed, documented deviation). An extra untracked script `scripts/repair-sofa-kv.ts` is present in the working tree but not mentioned in the task plan (confirmed); decide whether it belongs in this commit.

**Verdict**: APPROVED

## High-level view

The fix is the smallest correct one for the diagnosed break: the product's JSON is the source of truth for the build, so flipping status to `PUBLISHED`, mirroring `published: true`, and attaching real images is what moves it through `getCatalogue()` onto `/collection` and `/product/brown-sofa`. All schema invariants hold — `published` mirrors status, image `order` is a contiguous `0..3`, `primaryImage` references an owned id, every `alt` is non-empty — so both `ProductSchema` and the publish gate accept it. Identity and content fields (id, sku, slug, name, price, currency, category, description, material, tags, seo) are untouched; the only edits are the four image records, `primaryImage`, `published`, `status`, and `updatedAt`.

The test rewrite keeps its teeth: it reads the committed JSON and asserts `status: PUBLISHED`, `published: true`, four images, catalogue membership, publish-gate pass, and the exact WhatsApp name+SKU, so reverting the publish or mutating the SKU/name would fail it. Corner-sofa's draft guard is preserved.

The image binaries are the one loose end. A commit ships JSON but not R2 objects, so the live `/img/**` URLs 404 until the operator runs the upload. The upload script reads the production bucket name from the top-level `[[r2_buckets]]` block and refuses to reach into the preview env, is content-addressed/idempotent, and is deliberately not auto-run. The 21 MB of staged binaries and the `.agents/` tree are git-ignored and stay out of the commit.

### The publish flip and why it lands the product on both surfaces

`/collection` and `/product/[slug].astro` both derive their pages from `getCatalogue()` → `filterCatalogue()`, which admits only `PUBLIC_STATUSES = ['PUBLISHED','OUT_OF_STOCK']`. The base file sat at `DRAFT`, so it produced no collection row and no product page at all (a direct visit 404s). Flipping `status` to `PUBLISHED` with `published: true` is the minimal state change that makes the single public read path emit both pages. The recorded build confirms `dist/client/collection/index.html` lists the product and `dist/client/product/brown-sofa/index.html` exists.

The corner-sofa draft is left at `DRAFT`/`published: false`/`images: []`, so nothing else leaks into the catalogue and the empty-state path for the other draft stays exercised.

### Schema invariants all satisfied

The four image records clear every cross-field rule in `enforceProductInvariants`:

```
published: true          mirrors status PUBLISHED          → invariant 3 ok
primaryImage img_tchmzkuoeb == images[0].id (owned)        → invariant 5 ok
orders 0,1,2,3 contiguous from 0                           → invariant 6 ok
every alt non-empty; description ≫ 20; price 41990 set     → publish gate ok
```

`stockStatus: IN_STOCK` with `status: PUBLISHED` keeps the OUT_OF_STOCK equivalence in invariant 3 satisfied. `derivativeWidths` has five entries (under the `.max(12)` cap) and `derivativeFormats` is at the `.max(3)` cap. The targeted suite re-checks all of this against the committed bytes and passed 15/15 on re-run here.

### Identity and content preserved

The only changed lines versus `main` are the `images` array, the new `primaryImage`, `published`, `status`, and `updatedAt`. `id p_322e7n6mth`, `sku NGF-SOF-WBJZX0`, `slug brown-sofa`, `name`, `price 41990`, `currency INR`, `category sofas`, `description`, `material`, `tags`, and the `seo*` fields are byte-identical to the base, and sorted keys / two-space indent / trailing newline match the deterministic-bytes convention.

The `imageStatus`, `pendingImageOrder`, and `pendingImageAlt` markers survive unchanged from the draft era. They are inert passthrough fields the frontend ignores, but on a published product with four real images the "IMAGE REQUIRED — MANUAL ADMIN UPLOAD" string is now misleading — worth a follow-up cleanup.

### The test rewrite still bites

The rewritten suite reads the committed `brown-sofa.json` (not a fixture) and asserts the published state directly: `status PUBLISHED`, `published true`, four images, `primaryImage img_tchmzkuoeb`, `isCatalogueProduct` true, `checkPublishGate` ok, per-image non-empty alt and an R2-key regex `^products/p_322e7n6mth/img_[a-z0-9]{10}/original\.webp$`, plus the contiguous-order check. Reverting the publish, dropping the images, or changing the SKU/name would fail it — a meaningful anchor rather than a tautology. The exact WhatsApp assertion (message ends `(SKU: NGF-SOF-WBJZX0).` and single-decodes from the `wa.me` URL) is retained, and the corner-sofa draft guard (image-less, `DRAFT`, gate blocks solely on `images`) is preserved.

### R2 upload safety and the live-image gap

A git commit ships the product JSON but not the image bytes, which live only in git-ignored local R2. Until they are pushed to production R2, the live product renders but every `/img/**` URL 404s — if the operator forgets the upload, the storefront shows a product with broken images. `scripts/upload-brown-sofa-images-to-r2.ts` handles this out of band:

```
productionBucketName():
  read wrangler.toml, slice off everything from the first "\n[env." header,
  then find the MEDIA binding's bucket_name in the top-level block only
  → resolves "ngf-media" (production), never "ngf-media-preview"
```

Confirmed against `wrangler.toml`: the top-level `[[r2_buckets]]` MEDIA binding is `ngf-media` (line 139) and the preview binding `ngf-media-preview` lives under `[env.preview.r2_buckets]` (line 212), after the `[env.preview]` header at line 171 — so the slice-before-`[env.` logic cannot select preview. Keys are content-addressed and immutable, puts overwrite identical bytes, nothing is deleted, a `--dry-run` flag prints commands without uploading, and the script is not auto-run. The export helper reads local miniflare R2 only and writes into the git-ignored staging folder.

### Files that must not be committed

`.agents/` and `.agents/tasks/task-publish-brown-sofa/r2-export/` are both matched by `.gitignore` (verified via `git check-ignore`), so the ~21 MB of staged binaries and the task metadata stay out of the commit. `.wrangler/` is ignored too. Stage the two intended files (`data/products/brown-sofa.json`, `tests/unit/real-content-sofas.test.ts`) plus the scripts by name rather than `git add -A`, so the untracked `repair-sofa-kv.ts` decision stays explicit.

### The unrelated repair script

`scripts/repair-sofa-kv.ts` is present and untracked but is not part of the task plan (which names only the export and upload scripts). It is a local-only KV cache repair that deletes a stray `draft:p_eg3vtxpioj` duplicate and rebuilds `index:products` from committed files, with a hard guard refusing any `--remote` wrangler call. Safe in itself, but a separate concern from publishing this product: bundling it into the publish commit would mix two unrelated changes. Commit it separately with its own rationale or leave it out.
